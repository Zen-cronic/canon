What canon proposes to write

    Applied. Every line names the transport that actually carried it.

      The same engine, over every contested question in the catalog

      One hand-picked question is what you would show if it were the only one that worked. So: every concept in this catalog that more than one asset answers to, put through the same adjudicator, read-only. Contested means exactly that — not "unhealthy". Catalog health dashboards are a thing DataHub already ships.

      The refusals are the interesting column. canon abstains when the catalog does not carry enough to separate the candidates, and each abstention names what would settle it — so the refusals are a prioritised metadata backlog rather than a list of failures.

        What that changed for the next agent

        The write-back only matters if somebody else is better off. So: three stock retrieval strategies, run over this same catalog before and after the ruling landed. They read search and get_entities and nothing else — src/eval/downstream.ts imports none of canon's rules, scorer or resolver.

        The honest result is in the second row of each block. A governance-aware client already ranked the right table first on this catalog — the description, the owner and the Certified tag were enough, and the ruling did not have to fix that. What changed is that the staging copy behind the wrong board number stopped being served at all. A client that reads no metadata is unaffected either way.
